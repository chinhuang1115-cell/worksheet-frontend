## 0. 先講三個重要發現（會影響範圍）

1. **「已完成」只涵蓋 (a) 綜合練習（blocks／WeasyPrint／`zonghe_docx.py`）與 (b) mul2x1 乘法 7 個範本。獨立題型 N301A/B/D、N301C、N302A 仍走舊 docx 範本，`main.py` 呼叫的是 `gen_huachu4add.py`／`gen_tuiwei4sub.py`／`gen_tuiwei3sub.py`（讀 `templates/*.docx`），完全沒用 `blocks/`。** sample PDF 也是舊樣式（淡灰格、無 0.6u 進位列、無對齊箭頭）。因此下表 A 把它們列為「尚未套用」。若你的意思是「這些題型已改用 blocks」，請糾正我。
2. **全部範本都沒有「把計算格壓成圖片」的情況**（計算格皆為真表格；`word/media` 內只有插圖），所以 XML 都改得動。真正的風險在「粗橫線」：約一半範本的粗線是**獨立浮動直線圖形**（XML 名稱「直線接點」），另一半是表格 `sz=18` 粗框線（較穩）。
3. frontend 有**重複／過期的 PDF**：根目錄 `n2change_sample.pdf`、`fenfen_sample.pdf`、`pingfen_sample.pdf`、`sanbushu_sample.pdf` 與 `assets/` 同名檔內容不同（根目錄的是舊版；registry 指向 `assets/`）；另有 `assets/sub2noreg_app_*_sample.pdf`（底線）、`sub3noreg_app_std_sample.pdf`、`tuiwei3sub_yw_sample.pdf`、`tuiwei4sub_sample.pdf`、`fenfen_norem_sample.pdf` 等舊命名檔未被 registry 引用。盤點一律以 registry 引用的 `assets/` 為準（一開始我不小心用根目錄舊檔看了 n2change／sanbushu／pingfen，已重看 assets 版本並更正）。

## 需要使用者決策的問題

1. **N301A/B/C/D、N302A 這批（標題有「畫錢幣」的獨立題型）要不要**：(a) 沿用舊 docx 範本逐一改（批次 2、4），還是 (b) 直接改走已完成的 blocks／WeasyPrint 新架構（`blocks/*.py` 已有計算格與畫錢幣／畫記區，成品是 PDF，Word 只有檢視版）？(b) 一勞永逸但改變輸出型態（老師是否需要可編輯的 Word？）。
2. **減法借位列數（1 或 2 列）在 docx 範本如何處理**：規範要「依該題實際需借位次數」畫 1／2 列，但 docx 範本是固定列數。選項：(a) 統一畫 2 列（最簡單，但單借位題會多一列空白，違反規範）；(b) 依題型分範本（如 coin=1 列、dcoin／tally=2 列）；(c) 產生器依題目動態刪／加列（改動最大、風險最高）。三位數退位（sub3borrow、N302A）與四位數（N301C）都受影響。
3. **「不進位／不退位」題型是否仍畫進位／借位列**：規範 §6 只對「一位數加、乘」明說仍保留空列；N301A/B（不進位加法）、N202A／sub15／sub69（無借位減法）、addsub-mixed 不進位版怎麼處理？（保留空列＝版面一致；不畫＝省空間、少換頁。）
