# 互動版提示規格（強／弱／無提示）

> 機器可讀的完整規格在 [`dashboard/spec.json`](../dashboard/spec.json)，由儀表板（`dashboard/index.html`，GitHub Pages 的 `/dashboard/`）呈現成規格表、盤點與「新頁面套用」清單。**本檔說明用法與盤點結論；細節以 spec.json 為準，修改時兩邊一起更新。**
>
> 盤點依據：後端 repo `CLAUDE.md` 通則 1～21、`docs/guide/interactive-web.md`、`docs/guide/handoff-interactive-mul.md`（截至後端 commit `e8ae25b`，2026-10-14）。**依文件記載，未逐行比對程式碼**；實際行為以儀表板「逐項測試」為準。

## 三種難度對應紙本

| 互動版 | 紙本提示版型 |
|---|---|
| 強提示（level 3） | 完整提示 |
| 弱提示（level 2） | 淡化提示 |
| 無提示（level 1） | 自由列式（無提示） |
| （未實作）逐題漸退 | 逐題漸退淡化提示（見下方「未規格化」） |

URL 的 `mode=full|faded|free` 只決定**第一次**開啟的預設難度；之後以瀏覽器記住的 `wp_level` 為準，右上角可隨時切換（切換＝這題重來）。

## 盤點結論（27 項功能：已規格化 10、部分／有矛盾 15、未規格化 2）

### 未規格化（最需要先定）
1. **自動完成度（強提示自動帶入）**：只有錢幣進位定義了（拖完最後一包，剩下的 1 元自動走進個位）。加減、乘法、圓盤、位值都沒有「強提示時系統代做哪些機械步驟」的通則。
2. **逐題漸退**：spec 已有每題 `hint` 欄位，但介面不使用；「哪些提示先退、哪些後退」沒有規格（紙本版的設計是計算格先退、算式列後退、最後一題皆無）。

### 有矛盾，需先決定標準
- **連錯後正確選項閃動**：設計決定寫「連錯 2 次（無提示 3 次）閃」；提示對照表寫弱／無不閃。
- **弱提示有沒有懸浮提示框**：圓盤、錢幣有；加減、乘法概念／應用題／直式沒有（handoff：「使用者未要求」）。
- **無提示的放錯回饋**：加減仍有具體文字（連錯 3 次才提示）；錢幣進位只說「再試一次！」。
- **滑過朗讀**：三種難度完全相同，無提示是否該關？平板（觸控）沒有滑過，需另一種觸發方式。

### 只在部分題型規定、尚未通則化
提示文字寫法原則（簡單、生活化、「10 個一包」，只在錢幣題型明文）、語音唸完再停 2 秒才換畫面（僅錢幣）、數字念法（乘法有表，加減與錢幣散落各處）、上一步／下一步（僅直式計算）、拖曳即時變綠紅（直式乘法未載明）、成績紀錄（僅加減應用題）。

### 已規格化（可直接套用）
難度三段切換與記憶、不計時不扣分、拖曳為主＋點一下備援、作答紙、進退位引導閃動、位值標籤、語速與語音選擇、強提示自動朗讀、數字鍵盤亮暗、題目數字上色（加減）。

## 新建互動頁怎麼套用
1. 開儀表板「新頁面套用」分頁，輸入頁面名稱，勾選功能（「新頁面必備」預設勾選），複製產生的規格區塊給後端 session。
2. 標示「規格待補」的功能，先在「規格盤點」決定標準，再把決定寫回 `spec.json`（`status` 改 `done`、補 `levels`）。
3. 做完後在 `dashboard/catalog.json` 新增頁面變體；用 `python dashboard/check_catalog.py <後端路徑>` 確認沒有漏列端點。

## 維護規則（即時更新）
- **新增或修改互動頁 → 同一個 commit 更新 `dashboard/catalog.json` 與（若行為改變）`dashboard/spec.json`，並更新兩檔的 `updated`**。合併到 `main` 後 GitHub Pages 約 1 分鐘生效；儀表板每分鐘自動重抓，已開著的頁面會跳出「清單／規格已更新」。
- 測試勾選存在各人瀏覽器的 localStorage（key `dash_tests_v1`，以「頁面 id｜難度」為鍵），資料更新不會洗掉紀錄；換裝置用「匯出／匯入 JSON」。
